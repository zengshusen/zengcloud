# ZengCloud 架构说明

本文描述 ZengCloud 的系统分层、模块边界、权限模型、关键数据流与外部集成方式，作为后续脚手架与功能实现的统一参照。

## 1. 目标与约束

### 1.1 目标

把运维现场的「观测 → 研判 → 审批 → 执行 → 复盘」收敛到同一平台：

| 能力 | 含义 |
|------|------|
| 可审计 | 谁在何时对何对象做了何操作，可查询可导出 |
| 可确认 | 高危变更必须经过权限与人工确认点 |
| 可执行 | 任务、工单动作、智能体 Action 能落到主机 / 集群 / 数据面 |

### 1.2 非目标（当前阶段）

- 不替代专业 APM / 全量可观测商业产品的全部能力
- 不做成无审批的「一键全自动」黑盒运维
- 不以多租户 SaaS 为第一优先级（可按组织 / 业务线隔离演进）

### 2.1 分层职责

| 层 | 职责 | 不该做的事 |
|----|------|------------|
| 表现层 | 交互、可视化、权限感知的 UI 裁剪 | 直接持有 kubeconfig / 明文密钥做越权调用 |
| 接入层 | 协议、鉴权、序列化、实时通道 | 堆砌复杂业务状态机 |
| 领域服务 | 模块规则、工作流、审计、编排 | 前端特有的展示逻辑 |
| 适配器 | 对外部系统的连接与协议转换 | 绕过 RBAC 与审批直接暴露危险原语 |

## 3. 模块边界

### 3.1 运行概览

- **输入**：SLA / 工单及时率 / 告警 / 风险项等聚合指标
- **输出**：驾驶舱视图与下钻入口（到告警、工单、事件、资产）
- **依赖**：可观测、工单、事件、资产；自身尽量不写主业务数据

### 3.2 资产登记

- **核心对象**：一级业务、环境、资产、运维负责人、项目负责人
- **作用**：为权限范围、告警归属、工单路由、事件环境提供主数据
- **原则**：资产变更应可审计；负责人变更影响通知与审批路由

### 3.3 平台管理

- **核心对象**：K8s 集群、kubeconfig 引导信息、容器环境、容器、镜像
- **作用**：为任务中心与可观测提供执行目标与资源目录
- **原则**：凭证加密存储、最小权限拉取、操作留痕；禁止前端直连集群绕过后端

### 3.4 可观测性

- **子域**：平台总览、监控看板、日志中心、告警中心
- **数据来源**：Prometheus 兼容接口、Loki、ELK、ClickHouse 等
- **原则**：平台侧保存看板配置、告警路由与静默策略；时序 / 日志大体量数据留在外部存储，平台做查询编排与权限裁剪

### 3.5 任务中心

- **能力**：主机任务、K8s 任务、批量命令、Playbook、任务模板、执行记录
- **原则**：高危命令与批量变更绑定确认 / 工单；执行过程通过 Channels 推送进度；全量落执行记录

### 3.6 工单系统

- **类型**：应用发布、审批流、SQL 审计、事务工单
- **原则**：状态机清晰（草稿 → 审批中 → 待执行 → 已完成 / 已驳回 / 已关闭）；执行结果回写；与权限、资产负责人联动

### 3.7 事件中心

- **对象**：平台事件、外部事件、事件环境、事件源、排障复盘时间线
- **原则**：事件可关联告警、工单、任务与资产；复盘时间线是事后审计与知识沉淀的入口，可与 AIOps 知识图谱衔接

### 3.8 AIOps

- **能力**：智能助手、知识图谱、模型 / MCP / Skill / Action 配置、智能体审计
- **原则**：
  - 模型与工具调用全部审计
  - Action 默认只读；写操作必须经过确认策略（工单 / 人工确认 / 白名单）
  - Skill / MCP 作为受控扩展点，不可绕过 RBAC

### 3.9 权限审计（RBAC）

- **统一控制面**：后端 API 权限、前端路由、菜单、按钮、WebSocket 订阅
- **原则**：前端隐藏不等于授权；一切以服务端校验为准；敏感订阅按对象级权限过滤

## 4. 权限模型

### 4.1 概念

```text
用户 / 用户组
    └── 角色（Role）
            └── 权限（Permission：模块 + 动作 + 可选资源范围）
```

建议权限粒度至少覆盖：

- **模块**：如 `ticket`、`task`、`observe`、`aiops`
- **动作**：如 `view`、`create`、`approve`、`execute`、`admin`
- **范围**（可选）：业务线 / 环境 / 集群 / 资产集

### 4.2 前后端一致

| 控制点 | 前端 | 后端 |
|--------|------|------|
| 页面进入 | 路由 meta + 守卫 | 对应 list/detail API 鉴权 |
| 菜单展示 | 按权限树过滤 | 权限树 API 下发 |
| 按钮 | `v-permission` 等指令 | 写操作 API 再次校验 |
| 实时通道 | 仅订阅有权主题 | Consumer 内校验并过滤消息 |

### 4.3 审计日志最小字段

`actor`、`action`、`object_type`、`object_id`、`result`、`ip`、`request_id`、`created_at`、可选 `before/after` 摘要。

## 5. 关键工作流

### 5.1 告警 → 事件 → 工单 / 任务 → 复盘

```text
告警中心 ──产生/关联──▶ 事件中心 ──研判──▶ 工单（发布/变更/SQL）
                              │                │
                              │                ▼
                              └────────▶ 任务中心执行
                                              │
                                              ▼
                                         复盘时间线 + 审计
```

### 5.2 发布类工单

```text
提单申请 → 审批流（按角色/负责人）→ 确认执行 → 任务/平台适配器落地
    → 结果回写工单 → 通知相关人 → 审计归档
```

### 5.3 AIOps Action（写操作）

```text
助手意图 → Skill/MCP 规划 → 权限检查 → 确认策略
    →（通过）调用 Action → 执行适配器 → 智能体审计 + 业务审计
```

## 6. 数据与存储

| 存储 | 用途 |
|------|------|
| MySQL | 用户与 RBAC、资产与平台元数据、工单、任务定义与记录、事件元数据、看板与策略配置、审计日志 |
| Redis | 缓存、分布式锁、Channels 频道、短期任务状态、限流计数 |
| Prometheus 兼容 | 指标查询 |
| Loki / ELK | 日志检索 |
| ClickHouse | 大规模分析型查询（可选，按接入情况） |

**原则**：平台库存「配置与事实索引」，大体量遥测数据尽量不落主库全量副本。

## 7. 实时通信

- **传输**：Django Channels + Redis channel layer，ASGI 由 Daphne 承载
- **典型主题**：任务进度、告警推送、工单状态、事件时间线增量、助手流式输出
- **安全**：连接鉴权；主题按权限订阅；敏感字段脱敏

## 8. 外部集成适配器

| 集成 | 用途 | 注意点 |
|------|------|--------|
| Kubernetes API | 集群资源、工作负载、任务执行 | kubeconfig / Token 加密；命名空间范围控制 |
| Docker | 容器与镜像管理 | 宿主机/Daemon 访问隔离 |
| SSH | 主机命令与 Playbook | 凭据托管、命令审计、超时与并发限制 |
| Prometheus 兼容 | 指标与告警查询 | 多数据源与租户/业务线映射 |
| Loki / ELK | 日志 | 查询模板化，防止无界全文拖垮后端 |
| ClickHouse | 分析查询 | 只读账号优先 |

适配器应对领域层暴露稳定接口（如 `execute_command`、`apply_manifest`、`query_metrics`），避免业务代码散落各 SDK 细节。

## 9. 后端应用划分（建议）

```text
backend/apps/
├── accounts/          # 用户、认证、会话
├── rbac/              # 角色权限、审计
├── assets/            # 业务 / 环境 / 资产 / 负责人
├── platform/          # 集群 / 容器 / 镜像
├── observe/           # 看板 / 告警 / 日志查询编排
├── tasks/             # 任务模板 / 执行 / Playbook
├── tickets/           # 工单 / 审批 / SQL 审计
├── events/            # 事件 / 事件源 / 复盘时间线
├── aiops/             # 助手 / 图谱 / 模型与工具配置
└── overview/          # 驾驶舱聚合（可薄可厚）
```

跨模块调用优先走领域服务或明确的应用服务接口，避免循环依赖。

## 10. 前端信息架构（建议）

```text
/overview              运行概览
/assets                资产登记
/platform              平台管理
/observe               可观测性（总览 / 看板 / 日志 / 告警）
/tasks                 任务中心
/tickets               工单系统
/events                事件中心
/aiops                 AIOps
/admin/rbac            权限审计（管理端）
```

路由 `meta.permission` 与后端权限码对齐；无权限时统一 403 页，避免半残页面。

## 11. 安全基线

1. 密钥与 kubeconfig 仅存服务端，加密 at-rest，展示脱敏
2. 所有写操作与执行类 API 强制鉴权 + 审计
3. SQL 工单必须审计与可选执行沙箱 / 只读库策略
4. WebSocket 与 REST 使用同一身份上下文
5. 生产关闭 Debug，分离 `SECRET_KEY` / DB / Redis 配置
6. CSRF / CORS / 可信来源按部署域名收紧
